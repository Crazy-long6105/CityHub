# 模块六：多维度滑动窗口限流设计

日期：2026-10-20。

状态：结合现有 AOP、注解和 Lua 实现完成设计，尚未修改代码或执行压测。窗口和阈值为接口级初始配置。

## 1. 目标与范围

使用 Redis + Lua + Spring AOP + 注解，对高风险接口提供原子滑动窗口限流，支持全局（方法）、IP、用户三个维度，降低秒杀刷券、爬虫和突发流量对应用及下游的冲击。

模块顺序为 01 秒杀可靠性、02 支付关单、03 缓存穿透与逻辑过期、04 缓存一致性、05 Caffeine + Redis 二级缓存、06 多维度限流。

限流只负责“是否允许进入接口”，不替代模块一的 Redis + Lua 下单资格判断、不替代数据库唯一约束、不承担登录鉴权或业务幂等。秒杀入口先经过限流，再执行资格脚本；被限流不消耗库存，也不生成订单。

## 2. 现有实现与缺口

- 已有 `@RateLimiter`、`RateLimiterAspect` 和 `limiter.lua`，目前一个注解只有一个 `LimitType`，默认是方法级限流。
- 需要全局、IP、用户同时保护时，现有切面只能执行一个维度，不能一次原子判断多个维度。
- 脚本由应用传入本机毫秒时间，节点时钟偏差会改变窗口边界。
- `now .. '-' .. random` 作为 ZSET member 存在碰撞可能；碰撞会覆盖一条请求记录，使实际计数偏小。
- IP 直接优先相信 `X-Forwarded-For`，客户端在没有可信代理边界时可以伪造来源；列表也可能包含多个地址。
- 用户未登录时按 `anonymous` 共享用户桶，可能把所有访客混在一个桶里，也不能单独表达匿名 IP 防刷。
- Redis 返回空值或异常时，切面没有明确的保护策略；限流组件的异常不能静默放行高风险接口。
- 当前限流异常只返回统一消息，缺少维度、接口、拒绝次数和 Redis 错误指标。

## 3. 注解和维度模型

保留注解式接入，但将单个 `type` 扩展为 `dimensions`，支持一次声明多个维度；为兼容现有用法，单个 `type` 可迁移为只包含一个维度的简写。兼容规则固定为：`dimensions` 非空时以它为准，只有为空时才把 `type` 转换为单维度；若两者表达冲突配置，启动校验直接报错，避免运行时语义不确定。每个接口配置窗口秒数、单窗口上限、提示语及 Redis 故障策略，默认只作用于标注的方法。

建议维度：

| 维度 | Key 组成 | 适用 |
|---|---|---|
| METHOD | `rate:{method}` | 接口全局总量保护 |
| IP | `rate:{method}:ip:{trustedIp}` | 匿名刷接口、爬虫和单来源突发流量 |
| USER | `rate:{method}:user:{userId}` | 登录用户重复提交、刷券 |

同一个高风险接口可声明 `METHOD + IP + USER`。请求只有在**所有**桶都未达到上限时才被放行；任意桶已满就拒绝，且本次请求不能写入任何桶。对于只需要单维度的接口，仍可只声明一个。不要通过堆叠多个 AOP 注解完成多维度，否则前一个维度可能已经消费额度、后一个维度才拒绝，导致统计偏差。

用户维度要求登录时，未登录请求应在进入业务前被鉴权拦截；若公共接口确实允许匿名，USER 桶可使用 `anonymous`，同时建议配置 IP 维度，避免全体匿名用户共用一个过小的桶。不能把客户端传入的 userId 当作用户身份，统一使用 `UserHolder` 的服务端认证结果。

IP 解析采用部署配置的可信代理数量或可信代理网段：只有来自可信反向代理的转发头才可解析客户端地址，否则使用直接连接地址。`X-Forwarded-For` 多值按代理链规则从右向左校验，不能简单取第一个字符串。没有可信代理配置时，宁愿按网关地址限流并记录配置提示，也不把任意请求头当作真实 IP。

## 4. 原子 Lua 滑动窗口

一次脚本调用接收多个 Redis Keys、窗口和上限，使用 Redis 服务器 `TIME` 获取当前时间，不使用应用节点时间。脚本步骤：

1. 校验 Key 数量、窗口和上限；对每个 ZSET 删除 `score <= now-window` 的旧成员。
2. 读取每个 ZSET 的当前数量；只要一个数量达到上限，返回拒绝，不向任何 ZSET 添加当前请求。
3. 为每个维度写入本次请求成员，成员使用脚本内递增序列或包含 Redis 时间和足够唯一的随机/序号，不能依赖可能重复的时间戳字符串。
4. 为写入的 Key 设置不短于窗口的过期时间，避免空桶永久占用；必要时对已存在桶续期到窗口末端。
5. 全部成功返回允许及各维度计数；Lua 的原子执行保证多维度不会出现只消费部分额度。

边界采用半开窗口 `(now-window, now]`，清除 `<= now-window` 的成员；所有维度使用同一个 Redis 时间。脚本报错、参数非法或 Redis 执行结果未知时，AOP 不把异常当作允许，按接口策略快速返回系统繁忙/限流提示，并记录错误。普通低风险接口如确需故障放行，应在注解中显式选择 fail-open，不能作为默认行为；秒杀、登录、发券等高风险接口固定 fail-closed。

## 5. AOP 执行流程和响应

1. AOP 读取方法注解，解析接口方法名、维度和参数；不把请求体中的敏感内容拼进 Key。
2. 从服务端上下文取得可信用户身份，从受信代理规则取得 IP；检查值长度和字符集，防止构造超长或不可控 Redis Key。
3. 按稳定顺序构造多个 Key，调用同一 Lua；Redis 返回允许则进入 Controller，返回拒绝则抛出 `RateLimitException`。
4. 全局异常处理返回现有 `Result` 风格的明确繁忙提示，可增加错误码区分“被限流”和“限流依赖故障”，但不泄露内部 Key、用户或 IP。
5. 记录接口、维度、允许/拒绝、窗口配置版本、Redis 延迟和失败原因；日志按采样或聚合输出，避免每个请求打印完整身份。

不在 AOP 中 sleep、重试或查询数据库。窗口已经原子判断，业务异常、订单创建失败和支付失败不回滚已消耗的请求额度；这是流量预算，不是业务事务。

## 6. 参数与运维策略

窗口、上限、维度和故障策略先以注解为静态配置，后续可迁移到配置中心，但必须有版本和审计。秒杀接口现有 10 秒 10 次可作为单实例/用户维度的起点，不能直接宣称是全系统最佳阈值；全局方法限额需结合实例数和下游容量重新分配。

多实例共享 Redis 桶，因此阈值是全实例总量；不要按实例数再次无意放大。Redis 单节点故障时 fail-closed 会牺牲部分可用性，换取不让高风险流量直接冲击服务；Redis 集群脚本需要同一调用的所有 Keys 落在同一 hash tag，例如按方法和维度设计一致的槽标签，否则不能声称支持 Cluster。当前项目按单 Redis 实例验证。

Key 会随 IP/用户及方法增长，依靠窗口 TTL 和旧成员清理释放；需要观察 ZSET 大小、脚本耗时和拒绝率。用户注销、IP 变化不需要主动清桶，旧桶会自然过期。系统时间不参与判断，但 Redis TIME 所在服务器仍需正常运行。

## 7. 方案对比与收益

| 方案 | 优点 | 问题/成本 | 当前选择 |
|---|---|---|---|
| JVM 本地计数器 | 延迟低、实现简单 | 多实例不共享，重启清零，可被绕过 | 不作为主限流 |
| Redis 固定窗口计数 | 脚本简单 | 边界突刺明显，窗口交界可能放过两倍流量 | 不采用 |
| Redis + Lua 滑动窗口 ZSET | 多实例共享；按时间精细清理；脚本可原子组合多维度 | 每个请求保存成员，内存和脚本成本高，需要 TTL 与参数控制 | 本模块选择 |
| 令牌桶/漏桶 | 平滑流量、内存可能更稳定 | 语义和动态配置更复杂，和当前 ZSET 代码迁移成本高 | 后续有平滑需求再评估 |

收益应以实测表示：减少进入业务层的无效请求、阻止单 IP/用户刷券、保护下游；代价是 Redis 依赖、ZSET 内存和高峰脚本负载，以及 fail-closed 时 Redis 故障期间的部分不可用。

## 8. 修改顺序与验收

| 顺序 | 修改范围 | 完成依据 |
|---|---|---|
| 1 | 注解维度模型、Key 构造和可信 IP/用户身份 | 单维度兼容；多维度定义清楚；不信任伪造头或客户端 userId |
| 2 | 多 Key 原子 Lua、Redis TIME、唯一 member、TTL | 任一桶拒绝时其他桶不增加；边界和清理一致 |
| 3 | AOP 故障策略、异常码和指标 | Redis 异常不默认放行；业务方法只在允许时进入 |
| 4 | 秒杀及其他高风险入口接入 | 限流在资格脚本前；不同接口配置不串桶 |
| 5 | 并发、分布式和故障压测 | 统计计数、拒绝率、脚本耗时、Redis 内存和恢复行为有实测依据 |

必须验证：单窗口内允许数不超过配置；窗口边界清理正确；METHOD、IP、USER 任一超限都拒绝且不污染其他桶；并发多实例下总量符合配置；同毫秒大量请求不会因 member 冲突少计；客户端伪造转发头不能任意换 IP（在可信代理配置下）；未登录行为符合接口策略；Redis 故障时高风险接口 fail-closed；限流拒绝不会消耗库存或创建订单；脚本异常不会静默放行；窗口过期后 ZSET 自动释放。

本模块不把限流描述成防止所有恶意流量的安全边界，也不替代网关/WAF、验证码、鉴权或业务风控。必须记录关键指标并通过真实 Redis、并发压测和故障注入确认参数，不能把设计阈值写成已验证吞吐。
